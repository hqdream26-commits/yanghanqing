## 第五篇：大模型与 AI 工程——LLM、RAG、Agent 与部署

大模型（LLM）是当前 AI 领域最活跃的方向。它改变了 AI 应用的开发方式：从“训练小模型”转向“调用大模型 + 检索增强 + 工具调用 + 微调 + 部署”。掌握大模型与 AI 工程，意味着你能把语言模型能力转化为真实产品。

### 一、大模型基础

**预训练**：在海量文本上学习下一个 token 预测。  
**微调**：在特定数据上继续训练，包括全参微调、LoRA、QLoRA。  
**指令微调**：让模型学会遵循指令。  
**对齐**：RLHF、DPO、PPO，让模型更有用、诚实、无害。  
**提示工程**：Zero-shot、Few-shot、CoT、ReAct。  
**上下文学习**：模型根据提示中的示例临时学习。  
**多模态**：文本、图像、音频、视频联合建模。

### 二、RAG：检索增强生成

RAG 是当前企业落地最常用的方案。流程：

1. **文档加载**：PDF、Word、网页、数据库。
2. **切分**：按段落、标题、语义切分。
3. **嵌入**：用 Embedding 模型转成向量。
4. **向量库**：Faiss、Chroma、Milvus、Pinecone、Weaviate。
5. **检索**：相似度搜索、混合检索、多路召回。
6. **重排**：Cross-Encoder 或 LLM 重排。
7. **生成**：将检索内容放入提示，让 LLM 回答。
8. **评估**：忠实度、相关性、召回率、延迟、成本。

### 三、Agent：从对话到行动

Agent 让 LLM 具备规划、记忆、工具调用能力。核心组件：

- **规划**：任务分解、反思、重试。
- **记忆**：短期对话记忆、长期向量记忆。
- **工具**：搜索、计算器、数据库、API、代码执行。
- **执行循环**：观察 → 思考 → 行动 → 观察。
- **框架**：LangChain、LlamaIndex、AutoGen、CrewAI、Semantic Kernel。

### 四、微调与推理优化

**微调选择**：  
- 提示工程：最快、最便宜。  
- RAG：适合知识密集、需要更新。  
- LoRA / QLoRA：适合风格、格式、领域适配。  
- 全参微调：成本高，适合大公司。

**推理优化**：  
- 量化：INT8、INT4、GPTQ、AWQ。  
- KV Cache、PagedAttention。  
- vLLM、TensorRT-LLM、llama.cpp、Ollama。  
- 批处理、流式输出、缓存。

**部署**：  
- FastAPI / Flask 提供 API。  
- Docker 容器化。  
- Kubernetes 扩缩容。  
- 监控：延迟、吞吐、错误率、token 成本、幻觉率。

### 五、学习路线

**第 1 步：调用 API**  
用 OpenAI、Anthropic、通义、文心、DeepSeek 等 API 做聊天机器人。

**第 2 步：提示工程**  
学习结构化提示、Few-shot、CoT、角色设定、输出格式控制。

**第 3 步：RAG**  
用 LangChain + Chroma 做本地知识库问答。

**第 4 步：Agent**  
加入搜索、计算、数据库查询、代码执行工具。

**第 5 步：微调**  
用 Hugging Face + PEFT + LoRA 微调开源模型。

**第 6 步：部署**  
用 vLLM 部署模型，FastAPI 提供接口，Docker 打包。

### 六、推荐项目

1. 个人知识库问答：上传 PDF，做 RAG。
2. 客服 Agent：意图识别 + 知识检索 + 工单创建。
3. 代码助手：代码检索 + 解释 + 生成。
4. 论文阅读助手：总结、问答、引用定位。
5. 多模态应用：图像理解 + 文本生成。
6. 本地大模型：Ollama + Llama 3 / Qwen 部署。

### 七、伦理与安全

- **隐私**：不要上传敏感数据到第三方 API。
- **偏见**：模型可能放大训练数据中的偏见。
- **幻觉**：RAG 和引用可缓解，但不能完全消除。
- **版权**：注意训练数据和生成内容的版权。
- **安全**：提示注入、越狱、工具滥用。
- **对齐**：让模型符合人类意图和价值观。

### 八、常见误区

- 一上来就微调，其实提示工程 + RAG 更有效。
- 忽视评估，只看 demo 效果。
- 不控制成本，token 费用失控。
- 不考虑延迟，用户体验差。
- 不做安全防护，容易被提示注入。
- 盲目追新框架，忽视基础工程能力。

### 九、总结

大模型与 AI 工程的核心是：**用 LLM 作为推理引擎，用 RAG 接入知识，用 Agent 连接行动，用微调适配领域，用部署落地产品**。学习顺序应是：API → 提示工程 → RAG → Agent → 微调 → 部署。最终目标不是“会调模型”，而是“能解决真实问题”。
## 扩展学习笔记

### 这一篇要解决的问题

- 搞清楚学习对象是什么，避免一上来就陷入工具和教程碎片。
- 建立最小可执行路线，把知识点变成可以完成的小项目。
- 用复盘检查自己是否真正理解，而不是只完成了观看和收藏。

### 推荐实践方法

1. **先跑通一个最小案例**：不追求完美，先让代码、数据、结果完整闭环。
2. **再拆解关键概念**：把每个概念写成“是什么、为什么、怎么用、常见错误”。
3. **最后做一次迁移**：换一个数据集、场景或任务，验证自己是否能独立复现。

### 学习检查清单

- 我能不能用自己的话解释这个主题的核心概念？
- 我能不能指出它适合解决什么问题、不适合解决什么问题？
- 我有没有留下代码、笔记、图示或项目结果？
- 我能不能把它接到下一个阶段继续学习？

### 常见扩展方向

- **项目化**：把知识点做成小作品，比如预测、分类、问答、检索、自动化脚本。
- **工程化**：考虑数据质量、版本管理、部署方式和可维护性。
- **表达化**：把学习过程写成文章，训练自己讲清楚复杂问题的能力。

### 小结

大模型与 AI 工程 不适合只靠“看懂”完成。真正有效的学习，是每一阶段都留下可运行、可解释、可复盘的成果。
